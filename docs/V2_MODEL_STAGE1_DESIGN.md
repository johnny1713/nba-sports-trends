## 1.2 來源比對與 box score 稽核結果（2026-11-20，唯讀；報告在 `docs/reports/box_quality/v1/`）

**ESPN 失誤欄位的定義（同場比對 ESPN 原始 JSON vs BBRef）**

| | 其他 10 季（600 筆）| 2017-18（2134 筆）|
|---|---|---|
| ESPN `turnovers` | = 球員 TO 加總 600/600 | = 球員加總 **1/2134**；= BBRef「球隊合計 − 球員加總」（全隊失誤）**2127/2134** |
| ESPN `teamTurnovers` | = BBRef 全隊失誤 600/600 | 意義不明：與本隊 926/2134、對手 897/2134 相符 |
| ESPN `totalTurnovers`（目前儲存的值）| = BBRef 球隊合計 600/600 | = turnovers + teamTurnovers，平均 1.18 |
| ESPN 球員 TO 加總 vs BBRef 球員加總 | 100% | 2126/2134（99.6%）|
| 球員 TO 加總 + `turnovers` vs BBRef 球隊合計 | （不適用）| **2129/2134（99.77%）** |

- 結論（待審查）：其他 10 季 ESPN 與 BBRef 的失誤定義一致（球隊合計 = 球員失誤 + 全隊失誤）。2017-18 是 **ESPN 球隊統計欄位錯位**：
  `turnovers` 欄放了全隊失誤，`teamTurnovers` 欄放了不明數值，所以 `totalTurnovers` 是錯的。球員層級的 TO 正確。
  這是 ESPN 欄位錯誤，不是兩個來源的定義不同。
- 高度一致候選：「球員 TO 加總 + `turnovers`」。5 筆不一致都是 ±1，分散在 5 場、5 個月份、4 隊，方向 2 正 3 負，無集中、無固定方向。
- **未產生修正版**（使用者指示：核准前不得產生 derived）。
- 抽樣涵蓋：2017-18 該季 1230 場例行賽中，163 場本來就是 BBRef 補值（NO、CHI 全季 82 場皆是），其餘 **1067 場全部比對完成，0 場失敗**。
  NO、CHI 不在 ESPN 比對內；它們的失誤來自 BBRef 球隊合計，不受這個錯誤影響。

**其他欄位**：FGM/FGA/3PM/3PA/FTM/FTA/OREB/DREB 11 季同場一致 99.9%～100%（不一致共 4 筆，皆 ±1，全在 2017-18）。
`trb` 是定義差異：ESPN 在 2014-15～2020-21 的 trb 含全隊籃板（oreb+dreb≠trb），2021-22 起不含；BBRef 一律不含。模型不使用 trb。

**未解決（弱證據）**：2014-15～2016-17 BBRef 補值場次的失誤比 ESPN 場次少。以同一批對手比較（對手打 CHI/NO 的 BBRef 場次 vs 打其他隊的 ESPN 場次）差 −2.38／−1.72／−0.29。
ESPN 原生場次已確認兩源 100% 一致，所以最可能是 CHI/NO 防守風格（逼失誤少）；但補值場次沒有 ESPN 數字可以同場驗證，**不能排除來源差異**。BBRef 補值敏感度分析（第 8 節）會涵蓋這一點。

**Box score 合理性稽核 v1**：整季系統性異常只抓到 2017-18 tov（季平均 1.18 vs 前後季趨勢 14.3，0 值 33%）。
單筆 error：2017-18 tov=0 共 748 筆，其他季合計 7 筆（oreb=0 四筆、tov=0 三筆）。

## 2. 預測目標

| 目標 | 定義 | 主要模型輸出 |
|---|---|---|
| T1 勝負 | 主隊獲勝的機率 | P(home win) |
| T2 分差 | 主隊得分 − 客隊得分（含延長賽）| 預期值與分佈寬度 σ |
| T3 總分 | 兩隊得分合計（含延長賽）| 預期值與分佈寬度 |

T1 有兩種來源並列比較：(a) 直接的機率模型；(b) 由 T2 的預期分差與 σ 轉成機率（常態分佈）。
例行賽與季後賽**分開評估**；第一版只用例行賽訓練，季後賽只評估、不混入訓練。

## 3. 特徵設計（全部「賽前已知」；依序加入，每步都要比前一步好才保留）

計算時點：比賽當天美東 00:00 之前已完賽、且資料完整的比賽（`asof.games_before`）。
**同一天較早開打的比賽一律不用**；F1、F2、F4 的每一個特徵都只用預測日前已完賽的比賽計算。

| 階段 | 特徵族 | 內容 | 狀態 |
|---|---|---|---|
| F0 | 主場與場地 | 主場指標；**獨立的中立場資料表**（見 3.1）；泡泡區與觀眾受限期間指標 | 第一版納入 |
| F1 | 球季累計效率 | ORtg、DRtg、淨值、Pace；以出賽場數收縮到上季值與聯盟平均（收縮先驗只用前幾季）| 第一版納入；**2017-18 失誤問題解決前不用該季的回合數** |
| F2 | 近期狀態 | 指數加權淨效率（半衰期以場數計）、近 5／10 場 | 第一版納入 |
| F3 | 四因素 | eFG%、失誤率、進攻籃板率、罰球率（攻、守）| **欄位已盤點（1.1 節）；失誤率與進攻籃板率的定義一致性確認前暫緩** |
| F4 | 對手強度調整 | 每個比賽日以之前的比賽重解 ridge 版 SRS | 第一版納入 |
| F5-A | 賽程 | 休息天數、背靠背、4 天 3 賽、連續客場長度、近 7 天場數 | 第一版納入（只需賽程）|

| F6 | 陣容可用性 | — | **第一版不納入**：球員 ID 對應（ESPN／BBRef 兩套）、轉隊、補值與出賽紀錄完整性確認後再獨立評估 |

### 4.1 模型驗證規則（使用者 2026-11-20 補充）

1. 特徵族加入順序固定（第 3 節表格），**每一族都列出開發期逐季成績**（8 折各自的指標與相對前一步的配對差），不只看整體平均。
2. 開發期的特徵選擇一律用 walk-forward：第 k 折的任何選擇只用該折訓練資料。
3. **不得使用 2023-24 選擇特徵、超參數或模型**；2023-24 正式驗證只執行一次，於凍結之後，並留執行紀錄。
4. B0 的基準值（主場勝率、平均主場淨勝分、平均總分）**只用各折訓練資料計算**。
5. B1 Elo 的初始評分、主場優勢、K 值、分差修正、季間回歸比例**只在開發期決定**。
6. 模型比較一律使用**相同的測試場次**，並提供逐場配對差異與其信賴區間。
7. 2024-25、2025-26 完全鎖定：不參與訓練、選模或調參（`config.check_seasons` 強制）。

## 6. 評估指標

| 目標 | 指標 |
|---|---|
| T1 | Brier Score、Log Loss、校準分箱（附 Wilson 信賴區間）|
| T2 | MAE、RMSE |
| T3 | MAE、RMSE |

- 每項都附 **95% 信賴區間**（以比賽為單位 bootstrap；另做「以比賽日為區塊」的 block bootstrap 檢查同日相關性）。
- 模型比較一律用**成對差異**（同一批比賽的逐場損失差）與其信賴區間，不比較兩個獨立數字（`backtest/stats.paired_diff`）。
- 依球季、例行賽／季後賽、季初（前 15 場）／季中後分開報告。
- **市場比較**：開發期沒有賽前市場價格，不做。2023-24 可用多家真正收盤做有限比較；2024-25 收盤只能做揭露「單一來源、無時間戳」的有限比較，開盤不用。

## 7. 防止資料洩漏的檢查

| 檢查 | 方式 |
|---|---|
| 只用賽前資料 | 特徵函式只接受 `asof.games_before()` 的輸出；單元測試：在未來插入一場數據極端的比賽，特徵必須完全不變 |
| 同日比賽 | 以美東日期切，同一天較早的比賽不用（既有規則）；測試：同一天兩場，前一場的比分改成極端值，後一場的特徵不變 |
| 聯盟平均、收縮先驗 | 只用預測日之前的資料計算；先驗只來自前幾季 |
| 標準化、校準 | 只在訓練折擬合，套用到測試折 |
| 盤口隔離 | 特徵模組不得 import `odds_flags`／`clv`／`price_time`／盤口檔；輸入只有 games 與 teambox；測試檢查 import、輸入欄位，且 games 中的 odds_* 欄位不被讀取 |
| 鎖定測試期 | 載入資料時呼叫 `config.check_seasons`；測試確認訓練／選模流程碰到 2025、2026 會報錯 |
| 可重現 | 每次執行記錄程式版本、輸入檔 sha256、特徵清單、超參數；同版本重跑結果逐位相同 |
| 隨機性 | 固定亂數種子；walk-forward 本身不打亂 |

## 8. BBRef 補值敏感度分析

- **A 組**：只用 ESPN 原生 box score（BBRef 補值的比賽在效率類特徵中視為缺漏；比分來自 ESPN 記分板，Elo 不受影響）。
- **B 組**：ESPN＋BBRef 補值。
- 同一套 walk-forward 跑兩次，比較 T1～T3 的逐場損失差與信賴區間。只有 2014-15～2017-18 有補值，所以只比較 2015-16～2018-19 的評估折。
- 第一版不含 F6（球員層級），因此只比較球隊層級特徵。
- **定義一致性先行檢查**：在敏感度分析前，先以同場比對確認 ESPN 與 BBRef 的失誤、籃板定義是否一致（需另抓 BBRef 樣本，見第 10 節）。
- 每場比賽保留 `box_source` 標記，敏感度分析的兩組資料集由此標記產生，不另做推測。
- 差異的信賴區間排除 0：先調查原因，不進入下一步。
