## 2. 預測目標

| 目標 | 定義 | 主要模型輸出 |
|---|---|---|
| T1 勝負 | 主隊獲勝的機率 | P(home win) |
| T2 分差 | 主隊得分 − 客隊得分（含延長賽）| 預期值與分佈寬度 σ |
| T3 總分 | 兩隊得分合計（含延長賽）| 預期值與分佈寬度 |

T1 有兩種來源並列比較：(a) 直接的機率模型；(b) 由 T2 的預期分差與 σ 轉成機率（常態分佈）。
例行賽與季後賽**分開評估**；第一版只用例行賽訓練，季後賽只評估、不混入訓練。

## 3. 特徵設計（全部「賽前已知」；依序加入，每步都要比前一步好才保留）

計算時點：比賽當天美東 00:00 之前已完賽、且資料完整的比賽（`asof.games_before`）。同一天較早開打的比賽也不用。

| 階段 | 特徵族 | 內容 | 備註 |
|---|---|---|---|
| F0 | 主場 | 主場指標；泡泡區（2020-07-30 後）與 2020-21 觀眾受限期另設指標 | ESPN 中立場標記不可靠，改依日期判定 |
| F1 | 球季累計效率 | 每 100 回合得分（ORtg）、失分（DRtg）、淨值、Pace；回合數由兩隊 box 平均估計 | 以出賽場數做收縮：開季時偏向上季值與聯盟平均 |
| F2 | 近期狀態 | 指數加權的淨效率（半衰期以場數計）、近 5／10 場 | 半衰期只在開發期選定 |
| F3 | 四因素 | eFG%、失誤率、進攻籃板率、罰球率（攻、守各一）| 進攻籃板率需對手防守籃板：同場另一隊 box |
| F4 | 對手強度調整 | 以賽前所有比賽解 ridge 版 SRS（對手調整後淨效率）| 每個比賽日重解，只用過去 |
| F5 | 賽程與體能 | 休息天數、背靠背、4 天 3 賽、近 7 天場數、連續客場長度、移動距離與時區變化 | 需建 30 隊球場座標靜態表（含搬遷）|
| F6 | 陣容可用性代理 | 上一場有出賽的球員佔本季分鐘比例、前 N 場高分鐘球員缺陣 | **只是代理**：歷史沒有賽前傷兵名單；只用前幾場的 box score |
| F7 | 總分專用 | 兩隊 Pace、聯盟近期場均得分趨勢 | 聯盟得分十年間明顯上升：只能用過去的近期平均，不可用全期平均 |

**明確不使用**：任何盤口（開盤、收盤、賽後快照）、本場或未來比賽的任何資訊、賽後才知道的傷兵狀態。

## 4. 時間序列切分（walk-forward，不打亂）

```
2014-15            暖身：只提供歷史，不產生評估樣本
2015-16 … 2022-23  開發期：逐季 expanding window
                    第 k 折 = 用之前所有球季訓練 → 預測下一季（模型每季重訓一次，特徵每天更新）
2023-24            驗證期：開發期定案後，凍結前最後確認（次數有限，每次都記錄）
2024-25、2025-26   鎖定測試期：全部凍結後一次性執行（config.check_seasons 強制、holdout_log 留紀錄）
```

- 特徵選擇、半衰期、收縮強度、正則化強度：**只看開發期 8 折的合併結果**。
- 驗證期 2023-24：只用於「是否凍結」的確認；若因結果不好而改模型，改完必須回到開發期重跑，且記錄驗證期被看過幾次。
- 鎖定測試期：程式層級擋住（`HoldoutLocked`）；訓練、特徵選擇、調參、模型選擇的程式碼一律拒絕載入 2025、2026。

## 6. 評估指標

| 目標 | 指標 |
|---|---|
| T1 | Brier Score、Log Loss、校準分箱（附 Wilson 信賴區間）|
| T2 | MAE、RMSE |
| T3 | MAE、RMSE |

- 每項都附 **95% 信賴區間**（以比賽為單位 bootstrap；另做「以比賽日為區塊」的 block bootstrap 檢查同日相關性）。
- 模型比較一律用**成對差異**（同一批比賽的逐場損失差）與其信賴區間，不比較兩個獨立數字（`backtest/stats.paired_diff`）。
- 依球季、例行賽／季後賽、季初（前 15 場）／季中後分開報告。
- **市場比較**：開發期沒有賽前市場價格，不做。2023-24 可用多家真正收盤做有限比較；2024-25 收盤只能做揭露「單一來源、無時間戳」的有限比較，開盤不用。

## 7. 防止資料洩漏的檢查

| 檢查 | 方式 |
|---|---|
| 只用賽前資料 | 特徵函式只接受 `asof.games_before()` 的輸出；單元測試：在未來插入一場數據極端的比賽，特徵必須完全不變 |
| 同日比賽 | 以美東日期切，同一天較早的比賽不用（既有規則）|
| 聯盟平均、收縮先驗 | 只用預測日之前的資料計算；先驗只來自前幾季 |
| 標準化、校準 | 只在訓練折擬合，套用到測試折 |
| 盤口隔離 | 特徵模組不得 import `odds_flags`／`clv`／`price_time`／盤口檔；測試檢查 import 與輸入欄位 |
| 鎖定測試期 | 載入資料時呼叫 `config.check_seasons`；測試確認訓練／選模流程碰到 2025、2026 會報錯 |
| 可重現 | 每次執行記錄程式版本、輸入檔 sha256、特徵清單、超參數；同版本重跑結果逐位相同 |
| 隨機性 | 固定亂數種子；walk-forward 本身不打亂 |

## 8. BBRef 補值敏感度分析

- **A 組**：只用 ESPN 原生 box score（BBRef 補值的比賽在效率類特徵中視為缺漏；比分來自 ESPN 記分板，Elo 不受影響）。
- **B 組**：ESPN＋BBRef 補值。
- 同一套 walk-forward 跑兩次，比較 T1～T3 的逐場損失差與信賴區間。只有 2014-15～2017-18 有補值，所以只比較 2015-16～2018-19 的評估折。
- 球員層級特徵（F6）在補值比賽中的球員編號是另一套系統：F6 對這些比賽改為「該場缺陣代理不可用」，並在敏感度分析中單獨檢查。
- 差異的信賴區間排除 0：先調查原因，不進入下一步。

## 9. 風險清單

| # | 風險 | 影響 | 對策 |
|---|---|---|---|
| R1 | 年代漂移：節奏與三分球比例十年間大幅上升 | 總分模型偏差 | 總分只用近期聯盟水準；逐季報告殘差 |
| R2 | 2019-20 泡泡區、2020-21 觀眾受限 | 主場優勢與休息效應失真 | 依日期設期間指標；敏感度：排除這兩季重跑 |
| R3 | 歷史沒有賽前傷兵名單 | 模型對傷兵消息反應落後市場 | 只用代理特徵；如實預期「贏過市場」很難 |
| R4 | 開季冷啟動 | 前幾週誤差大 | 收縮到上季與聯盟平均；分段報告 |
| R5 | 逐步加特徵造成多重比較 | 開發期過度擬合 | 特徵族順序事先固定（本文件）；每族一次決定 |
| R6 | 反覆查看 2023-24 | 驗證期失去樣本外意義 | 查看次數記錄在報告；改模型後回開發期重跑 |
| R7 | 季後賽樣本小、對戰重複 | 結論不穩 | 季後賽只評估、分開報告 |
| R8 | ESPN 中立場標記不可靠 | 主場效應估計 | 不用該欄位，依日期與已知中立場賽事判定 |
| R9 | 2022-23 品質狀態為 FAILED（只因盤口）| 是否可用於訓練 | **請使用者確認**：box score 完整，建議納入 |
| R10 | 2025-26 尚未回補 | 鎖定測試期只剩一季 | 回補與品質審查另行排程，不影響本階段 |
| R11 | BBRef 補值的球員編號體系不同 | 陣容代理在 2014-15～2017-18 部分比賽失效 | 見第 8 節 |
| R12 | 回合數是估計值 | 效率特徵有誤差 | 用兩隊平均；文件化公式 |

## 10. 需要使用者決定

1. 2022-23（品質狀態 FAILED，只因盤口欄位）是否納入本階段的 box score 訓練與評估。
2. 驗證期 2023-24 可被查看的次數上限（建議：最多 3 次，每次記錄）。
3. 第一版是否只用例行賽訓練（建議：是；季後賽只評估）。
