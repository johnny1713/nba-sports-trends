## 1.2 來源比對與 box score 稽核結果（2026-11-20，唯讀；報告在 `docs/reports/box_quality/v1/`）

**ESPN 失誤欄位的定義（同場比對 ESPN 原始 JSON vs BBRef）**

| | 其他 10 季（**抽樣**，每季 30 場，共 600 筆球隊紀錄）| 2017-18（**全季逐場**，1067 場、2134 筆）|
|---|---|---|
| ESPN `turnovers` | = 球員 TO 加總 600/600 | = 球員加總 **1/2134**；= BBRef「球隊合計 − 球員加總」（全隊失誤）**2127/2134** |
| ESPN `teamTurnovers` | = BBRef 全隊失誤 600/600 | 意義不明：與本隊 926/2134、對手 897/2134 相符 |
| ESPN `totalTurnovers`（目前儲存的值）| = BBRef 球隊合計 600/600 | = turnovers + teamTurnovers，平均 1.18 |
| ESPN 球員 TO 加總 vs BBRef 球員加總 | 100% | 2126/2134（99.6%）|
| 球員 TO 加總 + `turnovers` vs BBRef 球隊合計 | （不適用）| **2129/2134（99.77%）** |

- 其他 10 季抽樣資料（共 600 筆球隊紀錄）全部符合預期：ESPN 與 BBRef 的失誤定義一致（球隊合計 = 球員失誤 + 全隊失誤）。
  ⚠️ 這是**抽樣結果**，不代表其他 10 季已全季逐場驗證。2017-18 是 **ESPN 球隊統計欄位錯位**：
  `turnovers` 欄放了全隊失誤，`teamTurnovers` 欄放了不明數值，所以 `totalTurnovers` 是錯的。球員層級的 TO 正確。
  這是 ESPN 欄位錯誤，不是兩個來源的定義不同。
- **使用者決策（2026-11-20）**：
  1. 暫不批准任何修正；**2017-18 所有依賴 turnovers 的特徵停用**（回合數估計、進攻／防守效率、Pace、失誤率）。
  2. 「球員 TO 加總 + `turnovers`」只標記為 **high-agreement candidate**，不得產生 derived 修正版。
  3. **不可用 BBRef 整季覆蓋 ESPN 資料。**
- 5 筆不一致的逐筆明細（Game ID、球隊、ESPN 三個欄位、球員加總、候選值、BBRef 球隊合計／球員加總／全隊失誤）見
  `docs/reports/box_quality/v1/tov_2018_candidate.md`：都是 ±1，分散在 5 場、5 個月份、4 隊，方向 2 正 3 負；
  3 筆差在球員層級、2 筆差在全隊失誤部分。沒有第三個獨立來源，無法判斷哪一邊正確，不做取捨。
- 比對範圍：2017-18 該季 1230 場例行賽中，163 場本來就是 BBRef 補值（NO、CHI 全季 82 場皆是），其餘 **1067 場全部比對完成，0 場失敗**。
  NO、CHI 不在 ESPN 比對內；它們的失誤來自 BBRef 球隊合計，不受這個錯誤影響。

**其他欄位**（兩種結果分開看）：
- 2017-18 **全季逐場**（2134 筆）：FGM/FTM/FTA/DREB/3PM 100%；FGA、3PA 各 1 筆、OREB 2 筆 ±1 不一致。
- 其他 10 季 **抽樣**（600 筆）：上述欄位抽樣資料全部一致。**這是抽樣結果，不代表全季逐場驗證。**
`trb` 是定義差異：ESPN 在 2014-15～2020-21 的 trb 含全隊籃板（oreb+dreb≠trb），2021-22 起不含；BBRef 一律不含。模型不使用 trb。

**未解決（弱證據）**：2014-15～2016-17 BBRef 補值場次的失誤比 ESPN 場次少。以同一批對手比較（對手打 CHI/NO 的 BBRef 場次 vs 打其他隊的 ESPN 場次）差 −2.38／−1.72／−0.29。
ESPN 原生場次已確認兩源 100% 一致，所以最可能是 CHI/NO 防守風格（逼失誤少）；但補值場次沒有 ESPN 數字可以同場驗證，**不能排除來源差異**。BBRef 補值敏感度分析（第 8 節）會涵蓋這一點。

**Box score 合理性稽核 v1**：整季系統性異常只抓到 2017-18 tov（季平均 1.18 vs 前後季趨勢 14.3，0 值 33%）。
單筆 error：2017-18 tov=0 共 748 筆，其他季合計 7 筆（oreb=0 四筆、tov=0 三筆）。

## 2. 預測目標

| 目標 | 定義 | 主要模型輸出 |
|---|---|---|
| T1 勝負 | 主隊獲勝的機率 | P(home win) |
| T2 分差 | 主隊得分 − 客隊得分（含延長賽）| 預期值與分佈寬度 σ |
| T3 總分 | 兩隊得分合計（含延長賽）| 預期值與分佈寬度 |

T1 有兩種來源並列比較：(a) 直接的機率模型；(b) 由 T2 的預期分差與 σ 轉成機率（常態分佈）。
例行賽與季後賽**分開評估**；第一版只用例行賽訓練，季後賽只評估、不混入訓練。

## 3. 特徵設計（全部「賽前已知」；依序加入，每步都要比前一步好才保留）

計算時點：比賽當天美東 00:00 之前已完賽、且資料完整的比賽（`asof.games_before`）。
**同一天較早開打的比賽一律不用**；F1、F2、F4 的每一個特徵都只用預測日前已完賽的比賽計算。

| 階段 | 特徵族 | 內容 | 狀態 |
|---|---|---|---|
| F0 | 主場與場地 | 主場指標；**獨立的中立場資料表**（見 3.1）；泡泡區與觀眾受限期間指標 | 第一版納入 |
| F1 | 球季累計效率 | ORtg、DRtg、淨值、Pace；以出賽場數收縮到上季值與聯盟平均（收縮先驗只用前幾季）| 第一版納入；資料範圍 `use_team_stats`（3.2）；**2017-18 依賴失誤的部分停用** |
| F2 | 近期狀態 | 指數加權淨效率（半衰期以場數計）、近 5／10 場 | 第一版納入；資料範圍 `use_team_stats`（3.2）|
| F3 | 四因素 | eFG%、失誤率、進攻籃板率、罰球率（攻、守）| 資料範圍 `use_team_stats`；**可用性逐因素判定**（3.4）：2017-18 失誤率不可用，eFG%、進攻籃板率、罰球率可用 |
| F4 | 對手強度調整 | 每個比賽日以之前的比賽重解 ridge 版 SRS | 資料範圍 `use_team_stats`；比分版可用、每百回合版依賴回合數（3.4）|
| F5-A | 賽程疲勞 | 休息天數、背靠背、4 天 3 賽、連續客場長度、近 7 天場數 | 第一版納入；資料範圍 `use_fatigue`：**所有實際出賽**（3.2）|
| F5-B | 移動 | 移動距離、時區變化 | **暫緩**：球場座標資料表建立並確認後才加入 |
| F6 | 陣容可用性 | — | **第一版不納入**：球員 ID 對應（ESPN／BBRef 兩套）、轉隊、補值與出賽紀錄完整性確認後再獨立評估 |
| F7 | 總分專用 | 兩隊 Pace、聯盟近期場均得分（只用過去）| 資料範圍 `use_team_stats`；**Pace 相關與總分相關分開**：Pace 依賴回合數，聯盟得分只用比分（3.4）|

**明確不使用**：任何盤口欄位（開盤、收盤、賽後快照、ESPN 的 odds 欄位）、本場或未來比賽的任何資訊、賽後才知道的傷兵狀態。

### 3.5 資料存取層與跨球季 fallback（第六輪，`nba_quant/data_access.py`，已實作）

所有特徵、模型、回測程式**只能**透過 `DataAccess(purpose)` 讀資料（結構測試：`nba_quant/features|models|backtest|render`
內出現 `read_jsonl_gz`、`data/raw`、分類表或附加賽路徑就失敗）。這一層強制：

| 防護 | 規則 |
|---|---|
| 用途 | 每次存取宣告用途：data_quality、feature_computation、training、feature_selection、tuning、model_selection、evaluation、backtest |
| 模型凍結前 | 2024-25 只有 data_quality 可讀；2025-26 任何用途都拒絕（含 data_quality）|
| 模型凍結後（第七輪）| `config.freeze_model()` 登記凍結 → 每季**分別** `holdout_begin([季], 'final_evaluation', …)`；每季一生只能登記一次；兩季都只能以 `final_evaluation` 用途、帶**該季**未出結果的 run_id 讀取 |
| **2023-24 驗證期（第八輪）** | 凍結前只能 data_quality；凍結後 `config.validation_begin(model_version, feature_version, params, data_version)` 登記**一次**（記錄凍結時間、程式版本），只能以 `validation` + run_id 讀取與輸出指標；完成後不得重跑；看過結果後再凍結模型 → `validation_independence()` 永久 False |
| **歷史特徵生成 `history_features`（第八輪）** | 不是自由讀整季的權限：必須給 as_of，只回傳 as_of 美東日期之前已完賽的比賽；不得讀目標球季之後的球季；**目標球季本身須已授權**（開發期放行；2023-24 須驗證 run；2024-25／2025-26 須該季正式最終測試 run），所以凍結前讀不到任何 2023-24 以後的資料；永遠不得輸出評估指標 |
| 評估指標 | 輸出前呼叫 `assert_metrics_allowed(seasons)`：2023-24 只能在驗證 run、2024-25／2025-26 只能在該季正式測試 run |
| 永遠不能讀鎖定期的用途 | training、feature_computation、feature_selection、tuning、model_selection、evaluation（開發期 walk-forward）、backtest |
| 結果 | 自動標上該季、分開保存（`holdout_results()` 依季回傳，不提供合併平均；結果含 combined／pooled 會被拒絕）|
| 獨立性 | 看過任一季結果後再凍結任何模型，或另一季用不同模型版本登記 → `holdout_independence()` 永久回傳 independent = False，報告必須揭露 |
| 時間 | 只回傳 as_of 的美東日期**之前**已完賽且資料完整的比賽；同日較早場次不回傳 |
| 範圍 | 依分類表的用途欄位篩選；未知範圍報錯 |
| 欄位 | 要求整季不可用的欄位（2017-18 tov）直接 `FieldUnavailable`；要求 tov 時排除 `tov_usable` = False 的 box 並記錄 |
| 盤口 | 不 import 盤口模組；回傳的比賽只含白名單欄位 |
| 特徵 | `require_features()`：未登記 → KeyError；不可用 → `FeatureRejected` |
| 紀錄 | 每次存取寫入 `log`：用途、球季、範圍、as_of、回傳筆數、排除原因 |

**跨球季 fallback（只選資料，不算數值）**

- 門檻是**預先登記的資料可用性門檻**（使用者第七輪接受）：`MIN_SAMPLE_F2` = 3、`MIN_LEAGUE_GAMES_F1` = 100。不是模型最佳化結果；
  未來若要調整，只能用開發期資料評估、不得查看鎖定測試期結果；數值由測試鎖住，改動須經核准。
- **F2 近 N 場**（`f2_window`）：只用 `use_team_stats` 範圍內、預測日前已完賽的比賽，由近到遠取。當季不足時，**只有上一季同一特徵可用才往回數**；
  遇到不可用的球季（2017-18）就停止，**不跳過它去湊 N 場**。可用場次 ≥ N → ok；3（`MIN_SAMPLE_F2`）≤ 場次 < N → partial（用目前可用樣本）；

- **F1 收縮先驗**（`f1_prior_source`）：上一季同一特徵可用 → 該隊上季值。不可用（2018-19）→ **當時可取得的聯盟平均**：

### 3.7 F1 球季累計效率（stage 2，`nba_quant/features/f1.py`；先驗 B 方案待核准：docs/reports/model_data/v1/f1_prior_B_proposal.md）

**定義**（每隊、每場預測；只用該場美東日期之前、同一球季、`use_team_stats` 範圍內已完賽的比賽）

| 量 | 公式 |
|---|---|
| 回合數（每隊每場）| FGA − OREB + TOV + 0.44 × FTA |
| 該場回合數 | 兩隊回合數平均 |
| 時間係數 | (48 + 5 × OT) / 48 |
| ORtg_raw | 100 × Σ得分 / Σ該場回合數 |
| DRtg_raw | 100 × Σ失分 / Σ該場回合數 |
| Net_raw | ORtg_raw − DRtg_raw |
| Pace_raw | Σ該場回合數 / Σ時間係數（每 48 分鐘）|
| F1 | (n × raw + M × prior) / (n + M)，n = 本季至今場數，M = 10 |
| 先驗 | 上季可用：W × 該隊上季全季值 + (1 − W) × 上季聯盟平均（W = 0.5）；上季不可用：3.5 的聯盟平均 fallback；上季沒有資料（2014-15）：本季至今 ≥ 100 場才用本季聯盟平均，否則 missing |

- M = 10、W = 0.5 是預先登記的預設值，**沒有用任何資料調整**；未來若要調整只能用開發期。
- 依賴：`F1.*` → ortg／drtg／net_rating／pace → possessions（fga、oreb、tov、fta，兩隊）＋ pts ＋ overtimes（Pace）。
- 每列輸出：四個特徵值、原始值（raw）、本季至今場數、資料期間、先驗來源與球季、M、W、狀態（available／available_prior_excluded／unavailable／missing）。
- 不使用季後賽、附加賽；盃賽冠軍戰納入。只透過 DataAccess；2023-24、2024-25、2025-26 一律被拒絕。

**2026-11-21 修正（公式與先驗規則不變；開發期 2014-15～2022-23 所有數值與狀態與 aff54ca 逐位相同）**

| 缺口 | 修正 |
|---|---|
| 1 缺 box 的比賽沒有輸出 | 賽程與特徵輸出分離：預測目標以 `DataAccess.games()` 逐場輸出，不需要該場 box。歷史比賽任一隊 box 缺漏（缺 box、缺欄位、失誤不可用）→ 不計算共同回合數、雙方都不累計，記錄於 `excluded`（場次、球隊、缺漏隊伍、原因、影響範圍）；每列另有 `excluded_history_games`。不以另一隊資料推測 |
| 2 零回合數與異常值 | 每隊回合數 > 0 且共同回合數 > 0 才有效，否則 `invalid_possessions` 排除並保留原始數據；累計回合數 ≤ 0 → `invalid`、不輸出數值（優先於 missing）。異常值只**警告**：每 48 分鐘回合數超出該季「中位數 ± 6 × 1.4826 × MAD」（box 稽核 v1 的方法），不排除、不影響數值；開發期 9,519 場實際分布 82.1～121.3、帶寬約 68～134，0 場被標記 |

### 3.3 `quality.py` 的 83 場問題：已決定採用方案 A（2026-11-20 第四輪）

**現況**：`season_report()` 用 `season_type == 2` 計算例行賽場數與每隊場數，盃賽冠軍戰被算進例行賽：
2023-24、2024-25 例行賽完賽 1231 場，兩隊（IND/LAL、MIL/OKC）各 83 場。

**影響範圍**
1. **PASS 狀態：無影響**。程式本來就容許 +1（`expected <= reg_final <= expected + 1`、`TEAM_GAMES_DEFAULT = (82, 83)`，
   註解寫明「NBA 盃冠軍賽可 +1」）；兩季的 `quality.json` 都是 PASS。
2. **盤口品質統計**：冠軍戰被歸到「例行賽」盤口覆蓋率的分母（每季 1 場 / 1231 場，約 0.08%）。這是盤口報告的分類，與模型資料無關。
3. **模型資料統計**：若直接用 quality.py 的數字當作「例行賽戰績」會多 1 場。新版模型資料統計不讀 quality.py，改讀分類表。
4. **可重現性（新發現的既有問題）**：在暫存目錄重跑 2016、2024、2025 的 `season_report()`：
   `quality.json` 與 `odds_flags.jsonl.gz` 位元組相同；但 `docs/reports/data_quality/<季>.md` 的逐家表格中，
   **同分的列順序會變**（2016、2024 各有一列換位置，數字相同）。原因是同分時排序依賴集合的迭代順序。
   報告內容（數字）可重現，**列順序不可重現**。

**決定：方案 A**
- `quality.py` 不修改，視為凍結的盤口品質 v1；既有盤口品質報告不重新產生、不修改；既有報告的排序問題不修正。
- 新增獨立的模型資料統計模組 `nba_quant/model_data_stats.py`（設計見下）。
- 未來新產生的報告一律加固定的次要排序鍵，相同資料重跑時輸出位元組相同。

**模型資料統計模組 v1 設計**（`nba_quant/model_data_stats.py`，已實作）
- 輸入：`data/reference/game_classification.csv`、`data/raw/espn/<季>/`、`data/raw/espn_playin/<季>/`。**不 import、不呼叫 quality.py**（有測試）。
- 每季、每種用途輸出：完賽場數、包含的 game_type、每隊場數最小／最大值、兩隊 box 完整場數與覆蓋率、
  box 來源（ESPN／BBRef）、失誤定義分布、可用於總失誤特徵的球隊 box 數、同一開賽時間的場數（Elo 排序決勝用）。
- 戰績檢查：`counts_for_standings` 的每隊場數必須是 82（2019-20：63～75、2020-21：72）。目前 11 季全部 OK，
  2023-24、2024-25 的盃賽冠軍戰不再被算成第 83 場。
- 輸出到新路徑：`data/audit/model_data/v1/summary.json`、`docs/reports/model_data/v1/README.md`。
- 固定排序：清單依（開賽時間, game_id）排序，字典依鍵排序；相同輸入重跑位元組相同（有測試）。
- 鎖定：2025-26 拒絕讀取；2024-25 標 `data_quality_only`。
- 這是資料統計，不計算任何特徵值、不做預測、不做評估。

**當時列出的方案（已採用 A）**
- **A（建議）：不修改 quality.py**。把它視為盤口品質 v1 的凍結程式（以 commit 為版本），既有報告與 PASS 完全不動。
  新增獨立的「模型資料統計」（讀 `game_classification.csv`，依 `counts_for_standings` 計算例行賽場數、每隊場數），
  輸出到新的路徑，不與盤口品質報告共用檔案。
- B：在 quality.py 加一個「模型資料用」的新函式，原本的 `season_report()` 一行不改；加回歸測試：在暫存目錄重跑
  全部球季，`quality.json` 必須與既有檔案位元組相同。缺點是新舊邏輯放在同一個檔案，容易誤改。
- 列順序問題：任一方案都**不重新產生**既有報告。若要讓未來的報告可重現，需在排序加上決勝鍵（例如 provider 名稱），
  但這會讓重跑結果與既有 .md 不同，所以只建議套用在未來的新報告，需另行核准。
- 已新增回歸測試（T24）：在暫存目錄重跑 2016 的 `season_report()`，確認 `quality.json`、`odds_flags.jsonl.gz` 與既有檔案位元組相同，

## 8. BBRef 補值敏感度分析

- **A 組**：只用 ESPN 原生 box score（BBRef 補值的比賽在效率類特徵中視為缺漏；比分來自 ESPN 記分板，Elo 不受影響）。
- **B 組**：ESPN＋BBRef 補值。
- 同一套 walk-forward 跑兩次，比較 T1～T3 的逐場損失差與信賴區間。只有 2014-15～2017-18 有補值，所以只比較 2015-16～2018-19 的評估折。
- 第一版不含 F6（球員層級），因此只比較球隊層級特徵。
- **定義一致性先行檢查**：在敏感度分析前，先以同場比對確認 ESPN 與 BBRef 的失誤、籃板定義是否一致（需另抓 BBRef 樣本，見第 10 節）。
- 每場比賽保留 `box_source` 標記，敏感度分析的兩組資料集由此標記產生，不另做推測。
- 差異的信賴區間排除 0：先調查原因，不進入下一步。
