## 問題 1：`f1_prior_source` 的計數集合與 F1 不一致

- F1 本身正確：ERROR 在門檻判斷前就被排除，門檻使用排除後的有效比賽數。
- `DataAccess.f1_prior_source()`（資料存取層的先驗來源規則，目前由參考實作 `f1_reference` 與測試使用，**F1 計算本身不呼叫它**）
  只用 `games()` 的場數，會把缺 box、ERROR、回合數無效的比賽算進 100 場。
- 合成重現：6 場非 A 隊比賽標為 ERROR 後，同一天 F1 判定 A 隊排除後只有 99 場（missing），
  `f1_prior_source` 卻數到 105 場並判定為「當季至今聯盟平均」。
- 實際影響：目前無（2014-15、2018-19 沒有 ERROR 或缺 box 的比賽）。
- 建議：讓 `f1_prior_source` 不再自行計數，改為呼叫與 F1 相同的有效比賽判定（同一個函式），或移除它的計數邏輯、
  由 F1 單一來源決定先驗來源；並加入「含 ERROR 比賽時兩者一致」的測試。

## 問題 2：audit 缺失時靜默放行，且無法證明某場已被稽核

- `box_audit_flags()` 在檔案不存在時回傳空集合，F1 照常計算，等於「默認所有資料正常」。
- audit v1 只存「有問題的紀錄」，沒有逐場的已稽核清單，也沒有稽核時原始檔的 sha256；
  若原始資料日後被重新回補或新增比賽，F1 會把未稽核的比賽當成正常。
- 實際影響：目前無（audit 存在、筆數與原始資料一致、原始資料自稽核後未變動）。
- 建議（需要你核准，屬於資料存取層與 audit 輸出格式的變更，不改 F1 公式）：
  1. audit 檔缺失 → 拋出錯誤（F1 不得在沒有稽核結果時計算）。
  2. 以唯讀方式為 audit v1 補一份「稽核涵蓋清單」：每季 teambox 檔的 sha256 與已稽核的 (game_id, team) 清單
     （由現有原始資料重新產生，不改原始資料、不改既有 flag 檔）；F1 讀取時比對 sha256，不符或某場不在清單內 → 拋出錯誤。
