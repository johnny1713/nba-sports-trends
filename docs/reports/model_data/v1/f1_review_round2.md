## 1. 回合數與效率計算

`team_poss = FGA − OREB + TOV + 0.44 × FTA`（每個欄位都取自該隊自己的 box）；`game_poss = 兩隊平均`；
本隊得分與失分都除以同一個 `game_poss` 總和；季累計以總量相除（測試：兩場回合數不同時，結果 ≠ 逐場效率平均）。

**實際比賽逐項計算：2022-10-18 PHI @ BOS（0 OT）**

| 隊 | PTS | FGA | OREB | TOV | FTA | 估算 Poss |
|---|---|---|---|---|---|---|
| PHI | 117 | 80 | 4 | 14 | 28 | 80 − 4 + 14 + 0.44×28 = **102.32** |
| BOS | 126 | 82 | 6 | 11 | 28 | 82 − 6 + 11 + 0.44×28 = **99.32** |

- 平均 Poss = (102.32 + 99.32) / 2 = **100.82**
- PHI ORtg = 100 × 117 / 100.82 = **116.05**；PHI DRtg = 100 × 126 / 100.82 = **124.98**
- BOS ORtg = 124.98、DRtg = 116.05（同一回合數基準，互為鏡像）
- 測試確認：PHI 下一場（2022-10-20）的 F1 原始值正好是這三個數字。

**實際資料範圍**（開發期 8 季、9,519 場）：該場回合數 82.1～145.6（中位數 100.5），沒有 0 或負值；
兩隊估算相差 > 8% 的有 63 場（box 稽核 v1 已列出），以兩隊平均吸收。

**問題 1（缺口，目前無影響）**：`compute_season` 只替「自己的 box 也完整」的比賽輸出賽前特徵。
某場的賽前 F1 本來不需要該場的 box，但若該場任一隊 box 缺漏，整場**沒有任何輸出列**（也沒有 missing 標記）。
合成資料重現：g3 的 C 隊失誤欄位為 None → g3 兩隊都沒有 F1 列。開發期 box 覆蓋 100%，目前沒有比賽受影響。

**問題 2（缺口，目前無影響）**：零回合數。`Acc.values()` 在累計回合數為 0 時回傳 None，之後以 `x = 0.0` 代入、
權重仍是 n——F1 被靜默拉向 0，狀態卻是 available。合成資料重現：一場回合數為 0 的比賽後，F1.ortg 從先驗 109.9
被拉成 99.9。實際資料最小回合數 82.1，不會發生。另外沒有回合數上下限的異常值檢查。

## 2. 收縮先驗

| 項目 | 實作 |
|---|---|
| 收縮 | `F1 = (n × raw + 10 × prior) / (n + 10)`，n = 本季至今場數；n = 0 時 F1 = prior |
| 上季球隊值 | 該隊上季 `use_team_stats` 全部比賽的總量相除（含盃賽冠軍戰）|
| 上季聯盟平均 | 上季所有隊場的總量相除；ORtg = DRtg（每一分同時是得分與失分），Net = 0 |
| 先驗（上季可用）| 0.5 × 該隊上季值 + 0.5 × 上季聯盟平均（測試以 DataAccess 重算驗證）|
| 上季不可用 | 本季至今 ≥ 100 場 → 本季至今聯盟平均；否則最近一個可用完整球季（2016-17）的聯盟平均 |
| as-of | 本季至今聯盟平均只累計預測日（美東）之前的比賽（測試：15 場抽樣與 DataAccess(as_of) 重算一致）|
| 隨日期更新 | 正常球季：整季固定（測試：每隊反推的先驗只有一個值）；2018-19、2014-15：本季至今聯盟平均每天更新 |

**問題 3：輸出沒有保存 prior value。** 目前保存 prior_source、prior_seasons、n_games、shrink_games（M）、
prior_team_weight（W）、raw，先驗值只能由 `((n + M) × F1 − n × raw) / M` 反推（測試就是這樣驗證的）。

**2018-19 先驗切換（符合 3.5 的規則，但定義不連續）**

| 時點 | 先驗來源 | 先驗 ORtg | 先驗 Pace |
|---|---|---|---|
| 切換前最後一天（2018-10-30）| 2016-17 聯盟平均 | 106.23 | 98.73 |
| 切換第一天（2018-10-31）| 2018-19 本季至今（剛滿 100 場）| 106.73 | **104.68** |
| 季末 | 2018-19 本季至今 | 107.82 | 102.39 |

- 切換是規則本身（當季至今 ≥ 100 場）的結果，程式行為與設計一致，切換只發生一次、不會切回（有測試）。
- 但**先驗 Pace 一夜之間 +5.95**：2016-17 的聯盟 Pace 比 2018-19 低約 3～4（兩年的聯盟趨勢），而季初 10 天的
  聯盟 Pace 又偏高。切換當天各隊只打了 5～7 場，先驗權重約 60%，所以 **F1.pace 在切換日跳約 3.5**；ORtg 只跳 0.5。
- 另一個結果：2018-19 整季的先驗都不含球隊資訊（各隊開季都從同一個聯盟平均出發），這是上季不可用的必然代價。

## 3. 2017-18 隔離

- 依賴：F1 四個特徵都經 possessions → tov，2017-18 全部 unavailable，不輸出數值（既有測試 + 狀態與規則一致的測試）。
- 實際路徑：`compute_season(2019)` 判定上季（2018）不可用後**完全不呼叫** 2018 的 `team_boxes`／`games`，
  只讀 2017（fallback）與 2019。
- **新增測試**：複製 2016～2019 原始資料到暫存目錄，把 2017-18 所有球隊 box（失誤、得分、出手、罰球、籃板、延長賽）
  與比分全部換成極端值後重算 2018-19 F1——**與原始資料的結果逐位相同**，且資料存取紀錄中沒有任何一次讀取 2017-18。
- 快取：F1 模組沒有快取、沒有模組層級狀態，不讀 `data/audit`、model_data 等預先計算檔（有測試）。

## 4. Pace 延長賽

- `overtimes` = 延長賽次數：ESPN 為 linescore 節數 − 4；BBRef 為 (球隊上場分鐘 − 240) / 25。
  以既有同場比對的 2,614 筆開發期球隊紀錄核對：ESPN 的 overtimes 與 BBRef 分鐘推得的次數 **100% 一致**。
  （刻意不讀 2023-24 以後的比對資料。）開發期分布：0 OT 10,136 場、1 OT 533、2 OT 68、3 OT 9、4 OT 3。
- 時間係數 `(48 + 5 × OT) / 48`；回合數本身不做每 48 分鐘換算，只有 Pace 除以時間係數（測試：同樣 box 改成 2 OT，
  ORtg、DRtg 完全不變，Pace 乘以 48/58）。

| 延長賽 | 實際比賽 | 該場回合數 | 時間係數 | 單場 Pace |
|---|---|---|---|---|
| 0 | 2022-10-18 PHI @ BOS | 100.82 | 48/48 = 1.0000 | 100.82 |
| 1 | 2022-10-19 NY @ MEM（NY 110.92、MEM 112.12）| 111.52 | 53/48 = 1.1042 | **101.00** |
| 2 | 2022-11-10 MIL @ OKC（MIL 121.68、OKC 116.36）| 119.02 | 58/48 = 1.2083 | **98.50** |

## 5. 鎖定與權限

F1 以預設用途 feature_computation 呼叫 2023-24／2024-25／2025-26 → 拒絕；validation、final_evaluation 沒有 run → 拒絕；
history_features 沒有 as_of → 拒絕（`compute_season` 不帶 as_of 讀整季，所以無法用歷史特徵用途繞道）；F1 不輸出指標。

**問題 4：`data_quality` 用途可以計算鎖定季的 F1。** `compute_season(..., purpose='data_quality')` 會被資料存取層放行
（2024-25 本來就允許 data_quality 讀取），因此可以產生 2024-25 的 F1 特徵值。這次以**合成的 2025 球季資料**重現
（6 列），沒有讀真實鎖定期資料。產生特徵值不是評估指標，但等於讓「資料品質」用途成為計算鎖定期特徵的後門。

## 6. 建議（未修改，等待核准）

| 問題 | 建議 | 會不會改變現有輸出 |
|---|---|---|
| 1 缺 box 的比賽沒有輸出列 | 以 `da.games()` 的比賽清單為準逐場輸出；該場自己的 box 缺漏只影響之後的累計，不影響它自己的賽前特徵 | 開發期不變（box 100%）|
| 2 零回合數 | 單場回合數 ≤ 0 或超出合理範圍（例如 < 60 或 > 160）時該場不進累計並記錄；`raw is None` 而 n > 0 時改為 missing，不得以 0 代入 | 開發期不變（最小 82.1、最大 145.6）|
| 3 缺 prior value | 每列加入 `prior`（四個先驗值）| 只增加欄位 |
| 4 data_quality 可算特徵 | `features/` 內的計算只接受 feature_computation、history_features、validation、final_evaluation 用途；data_quality 拒絕 | 不影響開發期 |
| 2.7 先驗不連續 | 三個選項：(A) 維持現狀並在報告揭露；(B) 上季不可用時改為連續混合：prior = (G × 本季至今 + K × 最近可用季) / (G + K)，G = 本季至今場數、K = 100（沿用已登記的門檻，不新增參數）；(C) 整季固定用最近可用季（2016-17），不切換。我建議 **B**：沒有跳躍、季初仍有基準、隨資料增加自然轉向當季 | 只影響 2018-19 與 2014-15 |

以上都不是公式中的效率定義（回合數、ORtg、DRtg、Pace 的算法不變）；B 會改變 2018-19 的先驗定義，需要你決定。
